# [feat] GitHub 저장소 링크 기반 키워드 추출 기능 추가

라벨: 없음
담당자: SeoHyun1024

---

## 작업 내용

- 현재 `/match/[role]/repository` 화면(`src/app/match/[role]/repository/page.tsx`, `src/components/experience/RepositoryForm.tsx`)은 `owner/repo` 형식 문자열을 최대 3개까지 입력받아 세션 스토리지에 저장하기만 하고, 실제 저장소 내용은 살펴보지 않는다.
- 사용자가 GitHub 저장소 링크(URL)를 입력하면 해당 저장소를 탐색하여(README, 언어 통계, 주요 의존성 등) 기술 스택/키워드를 추출하는 기능을 이 화면에 추가한다.
- 추출한 키워드는 이후 경험 입력·개인화 판단(`src/lib/personalize.ts`)에서 활용할 수 있도록 저장소 링크와 함께 브라우저에 보관한다.

## 완료 기준

- [ ] `/match/[role]/repository`에서 GitHub 저장소 링크를 입력하면 해당 저장소를 탐색해 키워드를 추출한다.
- [ ] 추출한 키워드가 화면에 노출되고, 다음 단계(경험 입력)로 넘어가도 값이 유지된다.
- [ ] 저장소 링크와 추출된 키워드는 URL에 노출되지 않고 브라우저 저장소에만 보관된다.
- [ ] 저장소 탐색이 실패하는 경우(비공개 저장소, 잘못된 링크, API 레이트 리밋 등)에도 기존처럼 "저장소 없이 계속" 흐름으로 이어갈 수 있다.

## 참고 사항

- 대상 라우트: `/match/[role]/repository`
- 아래 4가지 핵심 결정은 `src/lib/routes.ts`에 이미 반영되어 있으며, 이번 작업도 이 원칙을 따른다.
  1. 주요 화면 흐름에 쿼리 파라미터를 사용하지 않는다.
  2. 회사 결과 URL에는 회사와 직무를 모두 포함한다 (`/companies/[company]/[role]`).
  3. GitHub 저장소 링크와 추출된 키워드 등 사용자 입력값은 URL에 넣지 않고 브라우저(세션 스토리지)에 저장한다.
  4. 기본 결과와 개인화 결과는 동일한 회사·직무 URL을 사용한다.
- 관련 파일: `src/components/experience/RepositoryForm.tsx`, `src/lib/match-flow-store.ts`, `src/lib/routes.ts`, `src/lib/personalize.ts`
- 인증 없는 GitHub API 호출은 레이트 리밋이 낮으므로 탐색 실패/제한 시의 사용자 경험을 함께 고려한다.

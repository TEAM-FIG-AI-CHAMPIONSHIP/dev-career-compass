# ADR-001: 두 진입로를 경로 세그먼트로 분리한다

- 상태: 승인
- 결정일: 2026-09-12

## 맥락

서비스에는 관심 회사를 먼저 고르는 흐름과, 사용자의 경험에서 회사를 찾는 흐름이
있습니다. 기존 구조는 회사 결과를 `/{company}/{job}`에 두고 역매칭 결과를
`/match?job=backend`로 표현했습니다.

이 구조에는 세 가지 문제가 있었습니다.

1. 회사 슬러그가 `match`, `ui`, `api` 같은 제품 최상위 경로와 충돌할 수 있습니다.
2. 역매칭의 직무가 쿼리에만 있어 단계별 화면과 URL 구조가 일치하지 않습니다.
3. 공통 경험 화면이 `job`과 복귀 주소를 쿼리로 받아 핵심 이동 경로가 링크 문자열에
   의존합니다.

## 결정

회사를 먼저 보는 흐름은 `/companies`, 경험에서 찾는 흐름은 `/match` 아래에 둡니다.

```text
/companies/[company]/[role]

/match/[role]/repository
/match/[role]/experience
/match/[role]/result
```

회사 결과의 기본 상태와 개인화 상태는 같은
`/companies/[company]/[role]`에서 렌더링합니다. 개인화 입력이 필요하면 `/match`
아래의 저장소·경험 화면을 재사용하고, 원래 회사 결과 주소는 `sessionStorage`에
일시 보관합니다.

완성된 경험 입력은 기존과 같이 `localStorage`에 저장합니다. 저장소와 경험값은
URL, 서버 세션, 데이터베이스에 저장하지 않습니다.

## 결과

### 좋아지는 점

- URL만 보고 회사 흐름과 경험 흐름을 구분할 수 있습니다.
- 회사와 직무가 결과 URL에 모두 명시됩니다.
- 새로운 최상위 제품 경로가 회사 슬러그와 충돌하지 않습니다.
- 쿼리 파라미터 없이 저장소·경험·결과 단계가 각각 새로고침 가능한 페이지가 됩니다.
- 회사 결과 공유 링크에는 개인 경험이 포함되지 않습니다.

### 감수하는 점

- 회사 결과에서 입력을 시작할 때 복귀 주소를 위한 짧은 브라우저 세션 상태가
  필요합니다.
- `sessionStorage`를 사용할 수 없거나 입력 URL을 직접 열면 회사 결과 대신 해당
  직무의 `/match/[role]/result`로 이동합니다.
- 이전 `/{company}/{job}`, `/experience`, `/match?job=...` 링크는 새 구조에서 더
  이상 canonical URL이 아닙니다. 외부 공개 후 주소를 바꾸는 경우에는 명시적인
  리다이렉트 정책이 필요합니다.

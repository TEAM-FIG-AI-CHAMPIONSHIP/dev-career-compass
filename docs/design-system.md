# 디자인 시스템

컨셉은 **맥 터미널**입니다. 값은 `apps/web/src/app/globals.css` 에 있고, 이
문서는 값이 아니라 값을 적용하는 규칙을 정의합니다.

터미널이라는 인상은 어두운 바탕이 아니라 **창틀·신호등·셸 줄·고정폭 라벨**에서
나옵니다. 그래서 기본 테마가 라이트여도 컨셉이 그대로 섭니다. 맥 터미널의 기본
프로파일(Basic) 자체가 흰 바탕이기도 합니다.

---

## 테마

기본은 라이트입니다. 이 서비스는 글이 많고, 긴 한글 본문은 흰 바탕에서 더 잘
읽힙니다. 어두운 바탕에서는 밝은 글자가 번져(halation) 획이 많은 한글이 특히
손해를 봅니다.

테마는 **세 상태**입니다.

| 상태  | 루트 속성            | 의미                                         |
| ----- | -------------------- | -------------------------------------------- |
| light | `data-theme="light"` | 사용자가 라이트를 직접 고름                  |
| dark  | `data-theme="dark"`  | 사용자가 다크를 직접 고름                    |
| auto  | 속성 없음            | 운영체제 설정(`prefers-color-scheme`)을 따름 |

두 상태(라이트·다크)만 두면 "지금 시스템을 따르는 중"을 표현할 방법이 없어,
시스템 설정을 바꿔도 화면이 따라오지 않는 이유를 설명할 수 없습니다.

전환은 **세 칸을 다 펼친 토글**이고, **진입 화면에만** 둡니다. 아이콘 하나로
줄이면 자리는 아끼지만 지금 무엇이 켜져 있는지를 글자로 읽을 수 없습니다.
대신 상단 바에서 뺐습니다 — 거기 두면 200px 가까이 차지해 회사·직무 이름과
단계 표시를 밀어내는데, 테마는 한 번 정하면 다시 건드리지 않는 조작이라 모든
화면에 자리를 내줄 이유가 없습니다.

### 규칙

- 색은 **역할 이름**으로만 씁니다(`paper` `surface` `ink` `accent`). 컴포넌트는
  테마를 모르고, `:root` 한 곳에서 값만 갈립니다.
- 다크 값은 `@media (prefers-color-scheme: dark)` 의 `:root:not([data-theme="light"])`
  와 `:root[data-theme="dark"]` **두 곳에 같은 값**으로 둡니다. 한쪽만 고치면
  시스템 다크와 직접 고른 다크가 달라집니다.
- 첫 페인트 전에 `app/layout.tsx` 의 `THEME_INIT` 이 저장된 값을 붙입니다. 이
  줄이 없으면 다크를 고른 사람에게 흰 화면이 한 번 번쩍입니다.
- 고른 값은 이 브라우저에만 남습니다(`localStorage`, 키 `rm-theme`).

### 바탕과 창

맥의 관계를 그대로 따릅니다. **바탕은 데스크톱, 창은 글이 놓이는 면**입니다.

| 토큰      | 라이트    | 다크      | 역할                               |
| --------- | --------- | --------- | ---------------------------------- |
| `paper`   | `#eceef1` | `#0d0f14` | 페이지 바탕                        |
| `surface` | `#ffffff` | `#161920` | 창 — 카드, 패널                    |
| `sunken`  | `#f4f5f7` | `#11141a` | 파인 칸 — 입력, 보조 패널, 빈 상태 |

라이트에서는 창이 바탕보다 **밝고**, 다크에서는 반대입니다. 두 값이 같으면 창이
창으로 보이지 않습니다.

## 색

### 강조는 파랑 하나입니다

| 색             | 토큰                                                          | 쓰는 곳                                                                                |
| -------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 파랑           | `accent` `accent-ink` `accent-on` `accent-tint` `accent-line` | 누를 수 있거나 지금 켜져 있는 것 — 링크, `$` 프롬프트, 주 버튼, 선택된 항목, 현재 단계 |
| 빨강           | `warn` `warn-tint` `warn-edge`                                | 문제 — 입력 오류, 조회 실패, diff 의 `-` 줄                                            |
| 초록·호박·회색 | `stage-fit` `stage-step` `stage-far`                          | 상태 — 역매칭 3단계 배지 **안에서만**                                                  |
| 녹회색         | `comment`                                                     | 셸의 `#` 주석 줄. 랜딩 태그라인 전용                                                   |
| 중립           | `ink` `ink-soft` `ink-muted` `line` `line-strong`             | 그 밖의 전부                                                                           |

- **강조색을 둘 이상 두지 않습니다.** 파랑·초록·검정을 함께 쓰면 "강조"라는
  개념에 색이 셋이 되어 어느 것이 강조인지 사라집니다.
- 상태색은 배지 테두리 안에서만 삽니다. 버튼이나 링크로 새어 나가지 않기
  때문에, 화면에서 초록·호박·회색이 보이면 그건 **언제나 상태**라는 뜻입니다.
- `accent-on` 은 강조색 **위에** 얹는 글자색입니다. 테마마다 뒤집히므로
  `text-paper` 나 `text-ink` 를 직접 쓰면 한쪽 테마에서 글자가 바탕에 묻습니다.
- 숫자는 색 대신 **흰색 고정폭(`tabular-nums`)** 으로 눈에 띄게 합니다.
- 색만으로 구분하지 않습니다. 3단계 배지는 `FIT` `STEP` `FAR` 코드를, 출처는
  "블로그 5" 처럼 글자를 늘 함께 씁니다.

### 이름표 바탕 — `--chip`

칩 전용 한 톤입니다. 놓인 면이 무엇이든 한 단계 떠 보이게 하는 것이 유일한
일이고, 다른 곳에 쓰지 않습니다.

| 테마   | 값        | 놓이는 면                                     |
| ------ | --------- | --------------------------------------------- |
| 라이트 | `#dfe3e9` | `paper`·`surface`·`sunken` 중 무엇보다 어둡게 |
| 다크   | `#272d38` | 셋 중 무엇보다 밝게                           |

### 창 장식

`mac-close` `mac-min` `mac-max` 는 맥 신호등의 실제 색입니다. **제목 표시줄
밖으로 나가지 않습니다.** 화면마다 맨 위에 색이 셋 생겨 삭막함이 풀리고, 창이
창이라는 것도 즉시 읽힙니다.

## 타이포

본문은 **고딕**(`font-sans`, IBM Plex Sans KR)입니다. 고정폭 한글은 자간이
벌어져 긴 글에서 읽는 속도를 떨어뜨립니다.

워드마크만 **Archivo 800**(`font-display`)을 씁니다. **로고 한 곳에만** 씁니다 —
제목까지 이 얼굴로 쓰면 화면이 광고처럼 보이고, 터미널의 차분한 목소리와도 맞지
않습니다. 자간은 -3.5%로 조입니다.

고정폭(`font-mono`, IBM Plex Mono)은 **터미널의 말투가 필요한 자리**에만 씁니다.

- 셸 줄 — `$ refactor diff --me`
- 라벨과 코드 — `BLOG` `FIT` `[3] 경험 <`
- 숫자와 경로 — `1–12 / 16` `src/lib/personalize.ts`

### 크기

`globals.css` 에 정의된 단계만 씁니다. `text-[0.90625rem]` 처럼 임의의 값을 직접
쓰지 않습니다.

| 토큰           | 크기 | 적용 대상            |
| -------------- | ---- | -------------------- |
| `text-display` | 30   | 페이지 제목          |
| `text-h1`      | 23   | 단계 화면 제목       |
| `text-h2`      | 19   | 절 제목              |
| `text-h3`      | 16.5 | 카드 제목            |
| `text-body`    | 15   | 본문                 |
| `text-body-sm` | 14   | 카드 본문, 보조 설명 |
| `text-caption` | 13   | 칩, 메타             |
| `text-meta`    | 11.5 | 모노 전용 라벨       |

- 제목은 그 아래 내용보다 반드시 커야 합니다.
- 제목 단계를 건너뛰지 않습니다. 절이 하나뿐이면 바깥 제목을 두지 않습니다.

## 컴포넌트

### 창 — `TerminalWindow`

제목은 가운데가 아니라 **왼쪽**이고 `>_` 로 시작합니다. 신호등은 눌리지
않습니다 — 창을 닫거나 줄일 수 없으므로 버튼이 아니라 장식입니다.

진입 화면, 저장소 입력, 분석 중 화면, 내보내기 패널이 씁니다.

- 창은 **입력과 출력이 오가는 곳**에만 둡니다 — 저장소 입력, 분석 중, 내보내기,
  그리고 진입 화면. 고르기만 하는 화면(회사 목록, 직무 목록)에는 두지 않습니다.
  성격이 다른 화면에 같은 틀을 씌우면 창이 장식이 됩니다.

### 카드 — `Card` `CardLink` `cardStyle`

| 종류     | 스타일                                      | 적용 대상                          |
| -------- | ------------------------------------------- | ---------------------------------- |
| `static` | 창 바탕, 실선 테두리, hover 없음            | 제안 카드, 내 경험 요약            |
| `action` | hover 시 강조 테두리, 선택 시 테두리와 배경 | 회사, 직무, 경험 항목              |
| `cta`    | 강조 배경과 테두리                          | 개인화 입력 유도. 한 화면에 하나만 |
| `empty`  | 점선 테두리, 파인 바탕                      | 미선택 항목, 미구현 영역           |

- hover 는 **누를 수 있다는 약속**입니다. 눌리지 않는 카드에 주지 않습니다.
- hover 는 테두리만, 선택은 테두리와 배경을 함께 바꿉니다. 둘이 같으면 방금
  누른 카드 위에 커서가 있는 동안 골랐는지 아닌지 구분되지 않습니다.

### 고르는 화면은 같은 카드를 씁니다

회사 선택(`/companies`)과 직무 선택(`/match`)은 **같은 `action` 카드**를 씁니다 —
이름은 `text-h3`, 그 아래 개수 한 줄, 오른쪽 끝에 화살표, `min-h-24 p-4`.

고르는 화면이 둘인데 서로 다르게 생기면, 한쪽에서 익힌 "이건 누르는 것" 이
다른 쪽에서 다시 시작됩니다.

**터미널이라는 인상을 카드에 넣지 않습니다.** 그 몫은 화면 맨 위 `CommandLine`
한 줄이 맡습니다(`$ ls ./companies`, `$ jobs --list`). 카드까지 셸 문법을
입히면 컨셉이 앞서서 **누를 수 있는 것으로 읽히지 않습니다** — 실제로 목록을
`$ cd ./backend` 줄로 만들어 봤다가 되돌렸습니다.

### 숫자는 배지로 감싸지 않습니다

개수·횟수처럼 **누를 수도 없고 상태도 아닌 값**은 회색 알약에 넣지 않습니다.
고정폭 글꼴에 `tabular-nums` 로 적고 색은 `ink-muted` 입니다.

회색 바탕은 두 가지를 동시에 어깁니다 — 다크에서 `sunken` 이 `surface` 보다
어두워 창에 구멍이 뚫린 것처럼 보이고, "창만 둥글다" 규칙도 깨집니다.

### 태그 — `Chip` / `StageBadge`

영역 이름, 출처, 고른 경험, 저장소 키워드가 **모두 같은 모양**을 씁니다.

**이 제품의 칩은 전부 이름표입니다.** 누를 수 있는 칩은 없습니다 — 고르는 일은
`CheckboxCard` 와 `RadioCard` 가 맡습니다. 그래서 칩은 "누를 수 있게" 보일
필요가 없고, **읽히기만 하면 됩니다**.

| tone       | 의미                                       |
| ---------- | ------------------------------------------ |
| `neutral`  | 이름표. `bg-chip`, 테두리 없음             |
| `accent`   | 강조 표시 — 저장소에서 찾은 키워드 등      |
| `selected` | 칩이 고를 수 있게 되는 날의 짝. 아직 안 씀 |

- **칩은 바탕 한 톤으로 형태를 만듭니다. 테두리로 만들지 않습니다.**
  진한 테두리는 "조작할 수 있다"는 약속이라 이름표에 붙이면 거짓말이 되고,
  흐린 테두리는 같은 색 면 위에서 그냥 사라집니다.
- 그 바탕은 `--chip` 한 톤입니다. 흰색·검은색을 쓰면 안 됩니다 — 칩은 바탕
  (`paper`)·창(`surface`)·파인 칸(`sunken`) 위에 **모두** 놓이므로, 그 셋 중
  아무 값이나 고르면 그 면 위에서는 칩이 사라집니다. `--chip` 은 라이트에서
  셋보다 어둡고 다크에서 셋보다 밝습니다.
- 칩 안의 숫자(`ChipCount`)는 이름보다 조용하되 `ink-soft` 까지만 낮춥니다.
  칩 바탕 위에서 `ink-muted` 는 대비가 3:1 언저리라 작은 글자로는 읽기
  어렵습니다.
- 영역마다 다른 색을 주지 않습니다. 어느 영역인지는 적힌 이름이 이미 말하고
  있고, 목록은 근거가 많은 순서라 순서가 무게를 대신합니다.

### 버튼 — `Button` `ButtonLink`

| variant     | 쓰는 곳                                      |
| ----------- | -------------------------------------------- |
| `primary`   | 이 화면에서 할 한 가지. **한 화면에 하나만** |
| `secondary` | 되돌아가기, 부수 동작                        |
| `ghost`     | 지우기처럼 무게가 없어야 하는 것             |

높이 44px 는 손가락 최소 히트 영역입니다. 화면에서 크기를 덮어쓰지 않습니다.

### 체크박스

`[x]` 같은 글자가 아니라 **진짜 입력**입니다. 네모는 터미널처럼 각지게(2px)
두되 테두리를 진하게 해서 누를 수 있게 생기도록 합니다. 흐린 테두리는 "표시"로
읽히고 "조작"으로 읽히지 않습니다.

### 진입 화면

**화면 전체가 창 하나**입니다. 다른 화면은 상단 바 아래에 내용이 놓이지만,
진입 화면에서는 창이 곧 페이지입니다. 처음 만나는 자리에서 "이건 터미널이다"를
한 번에 말합니다.

창은 **남은 높이를 그대로 채웁니다.** 높이를 px 로 고정하면 화면이 조금만 낮아도
진입 화면부터 스크롤이 생깁니다 — **첫 화면에서 스크롤을 보게 하지 않습니다.**
`min-h-0` 과 `grow` 로 뷰포트에 맞춰 늘고 줄게 두고, 안쪽 내용은 세로 가운데에
둡니다. 그래서 창이 작아 보이지 않으면서도 스크롤이 생기지 않습니다.

창 안에는 **워드마크 · 주석 두 줄 · 진입 카드 두 장**만 둡니다. 셸 세션이나
diff 를 여기 넣지 않습니다 — 설명을 늘어놓는 자리가 아니라 두 갈래 중 하나를
고르는 자리입니다.

상단 바를 두지 않고 테마 전환만 남깁니다. 로고가 창 안에 큰 글자로 서 있는데
위에 또 작은 로고를 두면 같은 이름이 두 번 보입니다. 테마 전환이 있는 화면은
여기뿐입니다.

### 명령 한 줄 — `CommandLine`

화면 제목 위에 셸 명령을 한 줄 붙입니다. 이 화면이 무엇을 하는 단계인지를
제목보다 먼저, 개발자의 말로 말합니다.

```
$ github-scan --role backend
GitHub 저장소 (선택)
```

실제로 실행되는 명령은 아니지만 **이름은 화면이 하는 일과 같아야 합니다.**
장식으로 지어낸 명령은 한 번 읽히고 나면 거짓말이 됩니다.

지금 쓰는 이름은 이렇습니다. 화면마다 하나씩, 흐름 전체가 한 세션처럼 읽히게
같은 말투를 씁니다.

| 화면           | 명령                              |
| -------------- | --------------------------------- |
| 회사·직무 탐색 | `ls ./companies`                  |
| 회사 결과      | `analyze {회사}/{직무}`           |
| 직무 선택      | `jobs --list`                     |
| GitHub 저장소  | `github-scan --role {직무}`       |
| 경험 입력      | `experience --edit --role {직무}` |
| 경험 기반 결과 | `match --role {직무}`             |

진입 화면에는 두지 않습니다. 거기는 창 안에서 이미 셸이 돌고 있습니다.

입력이 있는 화면은 그 입력부를 `TerminalWindow` 로 감싸고, 줄마다 `$` 프롬프트를
답니다. 실행 버튼에도 같은 `$` 를 붙여 "이 줄을 실행한다" 가 한눈에 보이게
합니다. 창 제목은 상태가 바뀌어도 그대로 둡니다 — 분석 중에 이름이 바뀌면 다른
창처럼 보입니다.

### 되돌릴 수 있게

늘릴 수 있는 것은 줄일 수도 있어야 합니다. GitHub 저장소 칸처럼 "추가" 가 있는
자리에는 **지우기를 같은 화면 안에 둡니다.** 지우기는 칸 안 오른쪽 끝에 붙입니다
— 줄 밖에 두면 칸이 늘어날수록 버튼이 어느 줄의 것인지 눈으로 다시 이어야
합니다.

칸이 하나만 남았을 때는 칸 자체를 없애지 않고 내용만 비웁니다. 칸이 모두
사라지면 "추가" 를 먼저 눌러야 입력을 시작할 수 있어, 빈 화면에서 무엇을 해야
하는지 한 단계가 더 생깁니다.

### 단계 표시 — `StepHeader`

막대가 아니라 **카운터**입니다. 진행 막대는 "얼마나 남았나"를 말하지만 여기서
필요한 것은 "지금 어디인가"이고, 세 단계뿐이라 이름을 다 적을 수 있습니다.

```
[1] 직무 고르기 / [2] GitHub / [3] 경험 <
```

지금 단계에 붙는 `<` 는 셸의 커서 자리를 흉내 낸 것입니다.

## 제안 카드

제안은 **읽고 지나가는 글이 아니라 해볼 것**입니다. 한 문단으로 두면 세 줄을 다
읽어야 무엇을 하라는 건지 알 수 있어, 카드가 일곱 장 쌓이면 아무도 끝까지 읽지
않습니다.

목록은 데이터의 `steps[]` 를 그대로 씁니다. **문장을 나누는 일은 사람(또는 생성
단계)이 합니다** — 화면에서 문장 부호로 자르면 "…가 핵심입니다" 같은 조언까지
할 일로 섞입니다. `body` 는 개인화 쪽에서 계속 쓰므로 함께 둡니다.

### 새로 시작할 것

```
[재고 정합성·품절 반영]          ← 영역 칩
재고가 0이 되는 순간을 …          ← 제목
☐ 재고 테이블이 바뀌면 …          ← 해볼 것
☐ 어디까지 늦어도 괜찮은지 …
근거 2건 · BLOG                   ← 접어 둔 근거
```

### 이미 만든 것을 발전시킬 것

```
[주문·결제·배송 처리]
쇼핑몰 주문 API를 만들었다면           ← 13px, 흐리게
결제와 재고가 따로 놀 때 되돌리는 데까지  ← 16.5px, 진하게
```

**기호도 라벨도 쓰지 않습니다.** 출발점 문장이 "…만들었다면"으로 끝나 스스로
조건이라고 말하고 있어서, 앞에 라벨을 붙이면 같은 말을 두 번 합니다. 화살표도
제목 첫 글자를 밀어낼 뿐 새로 말해 주는 것이 없습니다.

관계는 **명도와 크기**로 말합니다 — 조건은 작고 흐리게, 갈 곳은 크고 진하게.
빨강·초록 diff 로도 보여줄 수 있지만 카드가 여러 장 놓이면 색이 너무 튑니다.

## 경험이 화면을 바꾸는 방식

경험을 넣으면 회사 결과 화면이 달라집니다. 규칙은 하나뿐입니다 — **이 제안이
고른 경험에 닿아 있는가.** 데이터에 적힌 항목 id 가 겹치는지만 봅니다.

| 데이터                         | 뜻                           |
| ------------------------------ | ---------------------------- |
| `NewSuggestion.coversItemIds`  | 이 제안이 쓰는 경험 항목     |
| `DeepenSuggestion.fromItemIds` | 이 제안이 전제하는 경험 항목 |

- **새로 시작할 것** — 표시만 하고 **순서는 그대로** 둡니다. 해본 기술이 들어간
  제안이 먼저 와야 할 이유가 없습니다. 오히려 안 해본 쪽에 배울 것이 많습니다.
- **발전시킬 것** — **순서를 바꿉니다.** 출발점(`from`)이 없는 사람에게는 제안
  자체가 성립하지 않아서, 성립하는 것부터 보는 편이 낫습니다. 같은 무리 안에서는
  데이터가 준 순서를 그대로 둡니다 — 다시 줄을 세울 근거가 없습니다.
- **전부 걸리면 배지를 붙이지 않습니다.** 모든 카드에 붙은 표시는 아무것도
  가르지 못하고 잡음만 됩니다.

점수도 퍼센트도 만들지 않습니다. 키워드를 추측해 맞추지 않습니다. 겹침은
데이터에 적힌 사실이고, 그 밖의 판단은 하지 않습니다.

역매칭(회사를 3단계로 나누는 일)은 아직 비어 있습니다 — 규칙이 정해지지
않았고, 임시 규칙을 넣으면 근거 없는 배정이 사용자에게 나갑니다.

## 선택과 내보내기

체크는 **진척 추적이 아니라 선별**입니다. 한 회사에 제안이 일곱 개씩 붙는데 다
할 수는 없습니다.

진행률 막대를 두지 않습니다. 로그인이 없으니 남길 곳은 이 브라우저뿐인데
체크리스트는 몇 주에 걸쳐 하는 일이라 기기를 바꾸면 사라집니다. **지켜주지 못할
것을 지켜주는 것처럼 보이는 UI 를 두지 않습니다.**

대신 고른 것을 마크다운 체크리스트로 내보내 각자 쓰는 도구(README, 노션, 이슈)로
가져가게 합니다. 한 번의 방문으로 가치가 끝나야 로그인 없는 서비스가 약속을 지킬
수 있습니다.

- 상태: `lib/suggestion-picks.ts` — 메모리에만 둡니다. 저장하지 않습니다.
- 화면: `components/result/PickedExport.tsx`
- 파일로 내려받지 않고 글로 보여줍니다. 붙여 넣을 곳이 대부분 웹 편집기라
  파일을 거치면 단계만 하나 늘어납니다.

## 움직임

- 움직이는 것은 화면당 **하나를 넘기지 않습니다.** 커서 깜빡임
  (`caret-blink`)은 셸 입력을 흉내 내는 자리에만 쓰고, 지금은 쓰는 화면이
  없습니다.
- 스캔라인(CRT 줄무늬)은 쓰지 않습니다. 어두운 화면에서만 성립하는 효과이고,
  흰 바탕에서는 종이에 묻은 때처럼 보입니다.
- 모든 움직임은 `motion-safe:` 뒤에 둡니다.

## 아직 정하지 않은 것

- `steps[]` 와 `coversItemIds` / `fromItemIds` 는 지금 `data/fixtures` 에 손으로
  적혀 있습니다. 파이프라인이 제안을 생성하게 되면 같은 형태로 뽑아야 합니다 —
  지금 적어 둔 값이 곧 본보기입니다.
- 역매칭 3단계(`reverseMatch()`)의 규칙. 화면은 세 칸을 모두 열어 둔 채 비워
  두고 있습니다.
- 회사 로고 이미지(`company.logoSrc`)가 들어오면 흑백으로 깎을지 원색을 살릴지.
  원색을 살리면 "강조는 파랑 하나" 규칙이 목록 화면에서 무너집니다.

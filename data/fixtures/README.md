# fixtures 는 화면용 임시 데이터입니다

**검증 결과가 아닙니다.** 기술 블로그와 채용 공고의 검증·확정은 담당자가 따로
진행 중이고, 회사 목록도 그 결과로 정해집니다. 여기 있는 파일은 그 결과가
나오기 전에 프론트가 화면을 완주시키기 위한 자리표시자입니다.

## 지금 들어 있는 것

### 내용이 있는 파일 — 하나뿐입니다

`oliveyoung/backend.json`. 근거로 적은 URL 은 올리브영 테크블로그의 실제 글이고
링크가 열리는 것까지 확인했지만, **어떤 영역으로 묶을지와 어떤 제안을 낼지는
화면을 채우려고 임의로 구성한 것입니다.** 분석 결과로 읽으면 안 됩니다.

### 속이 빈 조합 파일 — 직무 목록을 세기 위한 것

나머지 19개 파일은 `domains`, `suggestions`, `evidence` 가 모두 빈 배열입니다.
`/match` 의 직무 목록이 `data/fixtures/{회사}/{직무}.json` **파일의 존재**로
직무와 회사 수를 세기 때문에, 파일이 하나뿐이면 목록에 한 줄만 나와 화면을
확인할 수 없습니다.

근거와 제안을 지어내지 않고 파일만 둔 이유는, **없는 분석을 만들어 두면 나중에
진짜 결과로 오인되기 때문**입니다. 이 조합들의 회사는 모두 `collecting` 이라
회사 선택 화면에서 결과 페이지로 가는 링크가 걸리지 않습니다.

회사와 직무의 짝은 지어내지 않고 `data/research/job_postings/step6_summary.md`
의 직무별 회사 목록에서 가져왔습니다. 그 목록과 `index.json` 양쪽에 다 있는
회사만 남겼습니다. 그 결과 직무 목록에 이렇게 보입니다.

| 직무 | 회사 수 |
|---|---:|
| 서버·백엔드 | 8곳 |
| 웹 프론트엔드 | 5곳 |
| 데이터·AI | 4곳 |
| 모바일 | 3곳 |

**실제 집계치(18/14/9/4곳)가 아닙니다.** `index.json` 의 16개 자리표시자 회사와
겹치는 것만 남긴 수라서 더 적습니다.

`index.json` 은 S1 의 카드·페이지네이션·두 상태를 모두 그려 보려고 16개 회사
자리표시자로 만들었습니다.

- `oliveyoung` — `published`, 결과 페이지가 열립니다
- 나머지 15곳 — `collecting`, 목업 직무 조합만 선택 화면에 보이고 결과 링크는
  만들지 않습니다

회사 16곳은 **확정된 목록이 아니라 화면 상태를 확인하기 위한 값**입니다.

## 언제 사라지나

담당자의 검증 결과가 `data/published` 로 들어오면 웹은 그쪽을 읽고, 이 디렉터리는
빈 상태 확인용으로만 남기거나 통째로 지웁니다.

## 모양

`apps/web/src/types/data.ts` 가 이 파일들의 모양을 적어 둔 곳입니다. 계약이
아니라 웹이 읽기 위한 내부 타입이며, 파이프라인 산출물이 정해지면 거기에
맞춰 고칩니다.
